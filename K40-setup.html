K40 wiring and GRBL-LPC setup

K40 CO₂ laser cutter · MKS SBASE v1.3 with LPC1769 · GRBL-LPC · LightBurn

As-wired connections

SignalConnection and function
Firing gateP2.5 drives the BED low-side MOSFET. BED negative connects to the laser PSU’s active-low L input. P2.5 high turns Q4 on and pulls L low. BED positive is on the board supply rail and must stay disconnected from L.
BED indicator branchR30 and D14 were both removed, opening the series path from VIN0 to Q4’s drain. The BED indicator is disabled.
Power commandJ8 pin 3 (P1.23) feeds the level shifter’s low-voltage input. Its high-voltage output goes to PSU IN, formerly connected to the wiper of the removed 5 kΩ potentiometer.
Level shifter supplyPSU 5V supplies the shifter’s high-voltage side. The low-voltage side can be supplied from either of two sources:
  • J8 pin 6 (P4.28), the currently wired connection. The firmware drives P4.28 high as a GPIO output at boot (LEVEL_SHIFTER_SUPPLY_P4_28). A GPIO can source about 4 mA at near 3.3 V, which suits BSS138-type modules (about 0.33 mA per channel through the 10 kΩ pull-ups) and TXS/TXB-type shifters. The supply is only present while this firmware is running. It is off during power-up, reset and the bootloader, and with stock firmware.
  • J2 pin 2, the board’s regulated 3.3 V rail. This is always on and independent of firmware, and is the preferred source for heavier loads. Confirm connector orientation before moving the wire.
Earlier firmware left P4.28 as an input, so the shifter was fed only through the weak internal pull-up (about 50 µA). That can sag when PWM is low and leave PSU IN partly high.
Signal groundJ8 pin 1 (DGND), shifter ground and PSU signal ground are common.
InterlocksThe lid and water-flow switches are hardwired to the PSU’s WP protection circuit.

Local GRBL-LPC customisations

The checkout is based on cprezzi/grbl-LPC commit 72d029e and reports 1.1f.20171008. The local firmware artifact was verified to use P1.23 for PWM and P2.5 for the firing gate. The exact image currently flashed to the controller has yet to be identified.

  • The build selects CPU_MAP_MKS_SBASE, DEFAULTS_K40 and SPINDLE_PWM_PIN_1_23. P1.23 is the primary output for PWM1 channel 4. Its secondary output is disabled, leaving P2.3 available for A-axis step. Build configuration · Pin map
  • USE_SPINDLE_DIR_AS_ENABLE_PIN uses the remapped direction pin P2.5 as the active-high firing gate. With SPINDLE_ENABLE_OFF_WITH_ZERO_SPEED disabled, the gate can remain asserted at S0 and during G0 while spindle mode is active. M5 clears the gate through the spindle-stop path. Spindle control
  • The latest source removes P1.23 from the MKS control-input mask and cycle-start decoder when it is selected for PWM. Serial cycle start (~) remains available. This change passed an ARM build. Controller flashing and hardware verification of this change are pending. Control pin map · Control input decoder
  • An M0 pause or a GRBL Safety Door hold releases the firing gate. On resume, the split-output firmware now waits until the stepper loads the first segment above the configured PWM off value before reasserting P2.5. The gate stays released through the pause and any initial travel or zero-power segments. Ordinary S0 handling after the gate is restored follows the existing spindle-enable configuration. Hold and resume · Spindle control · Segment execution
  • Local K40 defaults include 20 kHz PWM, 68% maximum duty and 320 × 230 mm nominal XY travel. The compiled off and minimum duty defaults are 0% and 1%, matching the saved settings. Stored controller settings still take precedence. The 157.5 steps/mm XY value is calibrated, not the nominal 160. Compiled defaults
  • The MKS board uses a dedicated hardware reset input. P1.0 is excluded from the GPIO control mask, and P1.22 can still report its active-low state when it is the only configured control pin. P1.22 is the Safety Door input (ENABLE_SAFETY_DOOR_INPUT_PIN) and is left unconnected, because the lid and water interlocks go to the PSU. Its internal pull-up is now set explicitly in PINMODE3, so it reads as a closed door rather than relying on the reset default. If P1.22 is pulled low, Grbl reports the door open and blocks resume. Control pin map · Control input decoder
  • LEVEL_SHIFTER_SUPPLY_P4_28 configures P4.28 as a GPIO output driven high in system_init(), to power the level shifter’s low-voltage side from J8 pin 6. Comment it out if the shifter is moved to the J2 3.3 V rail. Build configuration · System init
  • PWM settings writes reject nonfinite values, frequencies that would give an invalid timer period, and duty cycles outside 0–100%. When the PWM is set up, the firmware also caps the minimum duty at the maximum and the off value at the minimum, so a mis-ordered $34/$35/$36 cannot invert the power curve. Stored values are not changed. Settings handler · Spindle control

Operating notes

  • The setup runs and the signal levels and PWM were checked in January 2026. Intermittent re-ignition after M0 prompted the resume fix. The rebuilt firmware image includes it. The fix still needs validation on the machine.
  • After flashing the P4.28 build, measure J8 pin 6 to DGND while firing at low power. It should hold close to 3.3 V.
  • For an affected cut, check that the saved G-code restores a positive S on the cutting move. If it does, comparing M4 with Constant Power (M3) on that layer can help determine whether speed-scaled power during acceleration contributes to the missed start. G-code parser · Motion and PWM updates
  • The exact PSU and level-shifter models, their behaviour across reset and power loss, and an independent tube-current ceiling remain unverified. $36 caps PWM duty. The installed analogue mA meter provides a current indication, with peak current under PWM still unverified.
  • The firing gate stays asserted at S0 and during G0 while the laser is on, so only 0% PWM keeps the tube off there. To check this, run M3 S0 with a G1 move and a G0 move and confirm the mA meter reads zero. If it does not, enable SPINDLE_ENABLE_OFF_WITH_ZERO_SPEED. The M0 resume deferral then needs reworking, because it is compiled only when that option is off.
